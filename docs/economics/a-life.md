# A-Life 自律経済モデル

A-Life (LLM) が CLI-Canister-EVM を通じて自律運営する経済設計。

## 責務分離

| 責務 | 担当 | ツール/メカニズム |
|------|------|-------------------|
| 開発 | A-Life | `lazy ask` |
| DevOps | A-Life | `lazy evm-lifecycle`, `lazy dfx-lifecycle` |
| 価値提供 | A-Life | CLI → Canister → EVM |
| 課金 | A-Life | ckETH, cycles |
| 意志・方向性 | Owner | Inception (語彙注入) |
| 市場センシング | Owner | 外界観測・判断 |
| 自己評価 | Owner | フィードバックループ |

## 自律ループ

```
Owner (Inception)
       │ 意志注入
       ▼
A-Life (LLM)
       │
       ├── lazy ask → 開発
       ├── lazy lifecycle → デプロイ/運用
       └── CLI-Canister-EVM → 価値提供
               │
               ├── 消費者 → 課金 (ckETH)
               │               │
               │               ▼
               │         維持費支払い (cycles/gas)
               │               │
               └─────── 再投資余力 → 次の開発 or 拡張
```

## コスト構造精査 (2025/01/14)

### LLM課金モデルの現実

| モデル | 例 | 月額 | 特徴 |
|--------|-----|------|------|
| **定額制** | Claude Pro | $20 | Rate Limit付き使い放題 |
| **定額制** | Claude Max | $100-200 | 高Rate Limit |
| **API従量** | Claude API | $3-15/MTok | 従量課金 |

**現実**: A-Lifeが定額制を使う場合、**LLMは固定費**となる。

### コスト構造の分類

| コスト要素 | 課金方式 | 固定/変動 | 備考 |
|-----------|----------|----------|------|
| ICP HTTP Outcall | 呼び出しごと | 変動 | |
| ICP Query | クエリごと | 変動 | |
| ICP Storage | 使用量ごと | 変動 | |
| EVM Gas | トランザクションごと | 変動 | |
| **LLM (定額制)** | 月額固定 | **固定** | Rate Limit内 |
| LLM (API従量) | トークンごと | 変動 | バースト可 |

### 1. 固定費の存在: △ 条件付き

```
定額制LLM選択時:
  固定費 = $20-200/月 (LLM定額)
  変動費 = ICP + EVM (従量)

API従量制LLM選択時:
  固定費 = $0
  変動費 = ICP + EVM + LLM (全て従量)
```

**結論**: 定額制LLM選択時は固定費が発生する。ただしスケールしても固定費は増えない。

### 2. 損益分岐点の存在

定額制LLM ($20/月) を前提とした場合:

```
損益分岐点 = 固定費 / 粗利率
           = $20 / 0.7
           = $28.6/月 の収益で黒字化

例: Tier課金 Standard (¥300/月 ≈ $2) × 15プロトコル = $30/月
```

**結論**: 損益分岐点は存在するが、非常に低い。

### 3. 利益率への影響

| 月間収益 | LLM固定費 | 固定費率 | 利益率 |
|---------|----------|---------|--------|
| $50 | $20 | 40% | 30% |
| $100 | $20 | 20% | 50% |
| $200 | $20 | 10% | 60% |
| $500 | $20 | 4% | 66% |
| $1,000+ | $20 | 2% | 68%+ |

**結論**: 収益 $500/月 超でLLM固定費の影響は軽微 (70%に収束)。

### 4. スケール戦略

| 規模 | 推奨LLMモデル | 理由 |
|------|--------------|------|
| 立ち上げ期 | 定額制 | 固定費だがRate Limit内で十分 |
| 成長期 | 定額制 + API併用 | バースト時はAPI |
| 大規模期 | API従量制 | Rate Limit解除、コスト最適化 |

```
立ち上げ: $20固定 で試行錯誤
成長:     $20固定 + 超過分API
大規模:   API従量 (固定費ゼロ回帰)
```

### 5. 非線形成長の余地: ✓ 依然あり

定額制LLMの固定費は**スケールに対して一定**:

```
収益 × 2 → LLM固定費は同じ → 利益率向上
収益 × 10 → LLM固定費は同じ → 利益率さらに向上
```

これは従来の人件費モデル（収益増 → 人員増 → コスト増）と異なる。

### 非線形成長ドライバー

| 成長ドライバー | 効果 | 非線形性 |
|---------------|------|----------|
| A-Life自律開発 | LLM固定費で価値創出増 | O(n) → O(n²) |
| Auditor Pool | 参加者増 → 信頼性向上 → 需要増 | ネットワーク効果 |
| プロトコル数 | 1 Canister で N チェーン | 限界費用逓減 |
| CLI→拡張 | Web/App/IoT/Robot | 顧客接点乗数 |

## 拡張経路

CLI が Consumer-facing DApp として成立した後、再投資余力に応じて:

| Phase | インターフェース | 技術基盤 | 備考 |
|-------|-----------------|----------|------|
| 0 | CLI | Claude Code | 現在 (ミニマル) |
| 1 | Web | Canister http_request | ブラウザUI |
| 2 | App | Canister API連携 | モバイル |
| 3 | IoT | Agent通信 | センサー/アクチュエータ |
| 4 | Robot | 物理世界インターフェース | 自律機械 |

インターフェースが変わるだけで、CLI-Canister-EVM のコアは同一。

## A-Life vs 従来開発

| 観点 | 従来開発 | A-Life |
|------|---------|--------|
| 開発コスト | 人件費 (固定的) | LLMトークン (変動) |
| スケール | 人員に比例 | トークンに比例 |
| 24/7 稼働 | シフト制必要 | 自動 |
| 品質保証 | レビュー人員 | lazy ask + Auditor Pool |
| 限界コスト | 逓増 | 逓減 |

## リスクと対策

| リスク | 対策 |
|--------|------|
| LLMコスト高騰 | モデル競争による価格低下を期待 |

| 意志のドリフト | Inception による語彙固定 |
| 規制リスク | 分散インフラ (ICP/EVM) |
